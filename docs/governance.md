# Harmony360 Governance

Harmony360 uses explicit governance boundaries so retrieved, generated, historical, or probabilistic material cannot silently become canonical truth.

## Core rules

1. Recovery Before Reinvention.
2. Evidence Before Assertion.
3. Canonical Before Convenience.
4. Reproducibility Before Automation.
5. Governance Before Promotion.
6. One Runtime, Many Products.
7. Deterministic Rules Before Probabilistic Assistance.
8. Human Oversight Is a System Feature.
9. Partial Failure Must Be Survivable.
10. Every Material Output Must Be Traceable.

## Canonical lifecycle

```text
DISCOVERED
→ CLASSIFIED
→ UNDER_REVIEW
→ EVIDENCE_PENDING
→ EXPERIMENTAL
→ OPERATIONAL
→ CANONICAL
→ DEPRECATED / QUARANTINED / ARCHIVED
```

Promotion to `CANONICAL` requires evidence collection, dependency validation, risk review, a recorded decision, and a governed snapshot.

## Evidence rule

Every material finding, recommendation, canonical selection, conflict resolution, and customer-facing claim should retain:

- source asset identifier
- precise source locator when available
- extraction or creation method
- confidence or deterministic basis
- creator identity: rule, model, analyst, or system
- review status
- version and timestamp

## Retrieval authority boundary

Retrieval relevance is not authority. A retrieved item preserves the authority class and source registry assigned by the governed knowledge estate. Similarity scores may rank evidence; they may not promote it.

## Human oversight

Human approval is required for high-impact promotion decisions, Growth and Enterprise customer deliverables, policy changes, irreversible deletion, security exceptions, and autonomous actions not explicitly approved by policy.

## Failure philosophy

Each processing stage should record:

- state
- errors
- retry eligibility
- produced artifacts
- evidence and lineage
- reconstruction information

The goal is resumable, reconstructable processing without corrupting prior evidence.
